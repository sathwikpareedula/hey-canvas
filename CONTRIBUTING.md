# Contributing to Hey Canvas

Thanks for your interest in improving Hey Canvas. This is an independent student-built, local-first academic workspace.

## Before contributing

- Open an issue to discuss substantial changes before implementing them.
- Keep Canvas integration read-only. Do not add assignment submission, grade changes, or other Canvas write operations.
- Never commit Canvas tokens, `.env`, student records, grades, real course files, personal databases, machine-specific paths, or private logs.
- Use synthetic fixtures for tests, screenshots, documentation, and bug reproductions. Do not include real institutional course content without permission.
- Do not expose the local backend or Ollama to public network interfaces.
- Treat retrieved documents as untrusted input. Do not allow course content to override application instructions or cross course boundaries.
- Do not claim that a deterministic synthetic response was generated by Ollama or that synthetic tests establish real-model accuracy.

## Development and verification

Follow [Windows setup](docs/SETUP-WINDOWS.md) for installation and the synthetic demo. The demo does not require a Canvas account or local Ollama model.

Before opening a pull request, run the checks relevant to your change:

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests
.\.venv\Scripts\python.exe -m ruff check backend
.\.venv\Scripts\python.exe -m mypy
cd frontend
npm ci
npm run lint
npm run typecheck
npm run test
npm run build
npm audit --omit=dev --audit-level=high
```

GitHub Actions also runs backend, frontend, browser, Windows, and history/working-tree secret scans on pull requests. Do not merge failing checks or bypass security review.

## Pull request expectations

Explain what changed, why it changed, how it was tested, and any remaining limitations. Provide synthetic screenshots for UI changes. Keep unrelated refactors out of security fixes. Review dependencies and license compatibility before adding packages.

Security vulnerabilities and suspected credential exposures should **not** be reported with secrets or exploit details in a public issue. Follow [SECURITY.md](SECURITY.md) for private reporting guidance.

Contributions are submitted under the repository's [MIT license](LICENSE); only contribute material you have the right to license.
